`KV Cache skipped (no-op pool)`, 57 s to healthy. Decision requests with
images are accepted since fork `6a18a8d05e` (the refusal was a contract
guard, not a kernel limit).

- Canary vs the MI350X v2.2 golden: 112/112 same answer, max |Δp| 0.021,
  two passes identical (both modes).
- Cross-host set, 4,705 requests (3,430 text, 1,275 with images):
  every request 200, usage identical to the MI350X.
- **KV-free vs paged on the same H100: bit-identical on all 6,125
  questions** (max |Δp| 0.0), images included. The KV-free path changes
  nothing in the numerics; it only skips the pool.
- H100 (either mode) vs MI350X (triton): 98.58 % same answer, median |Δp|
  0.0017, p99 0.036, max 0.28 on one tic-tac-toe `empty_count` image
  question (a count-type question whose mass is spread over many bins; the
  MI325X also moves 0.09 there). Same disagreement rate as MI325X vs MI350X
  (98.6 %) and fork vs stock on one host (98.1 %): chip and kernel rounding
  on near-tie questions.

## Joint schema head (Clef-style) on the KV-free path

The P3 merged backbone and its fp32 schema head (copied from the MI350X
host) served as `standardthinking/standard-schema-8b` with
`--decision-readout-path /opt/engine/schema-head` on the same sm90
profile: 56 s to healthy, the layer-25 tap and final-norm tap captured
through the raw-K/V prefill like any other forward.

- Cross-host set vs the MI350X schema engine's 2026-10-04 answers (the
  three text eval sets and the 1,275 image pairs; 4,485 requests, 5,905
  questions): **99.46 % same answer**, median |Δp| 0.0011, p99 0.023, max
  0.134 (one image question). Image sets 97.8-100 %.
- `assistant_prefix` is refused with 422 `assistant_prefix_not_supported`
  (100 requests), as on the readout engines with a learned head.
- Throughput, c16: small-4q 46.3 req/s, big-64q **9.6 req/s** (614
  questions/s; the readout engine does 2.9), image 4q 23.9 req/s. The
  MI350X schema engine did 55.8 / 10.1 / 25.7.

The same schema engine through the paged pool (`KVFREE=0`) answered the
set **bit-identically** (6,025 questions, max |Δp| 0.0) at the same
throughput (45.6 / 9.4 / 23.5 req/s): the KV-free path is a pure memory
saving for the schema head as well.

## Committed performance profile

Retain `GPU_PROFILE=sm90`, `ATTENTION_BACKEND=fa3`, `KVFREE=1`, BF16,
and `MAX_RUNNING_REQUESTS=32` for the verified readout configuration.
The launch profile serves both text and images through this path. AMD's
`AITER_OPS` override is rejected on NVIDIA profiles rather than silently
changing a different GPU configuration.

The readout path is the measured winner for short 4q requests (89.3 req/s
at c16 versus the schema engine's 46.3). The schema head is the measured
winner for 64q (9.6 versus 2.93 req/s) and images (23.9 versus 18.2).
These are distinct trained model/head paths, not interchangeable kernel
flags; choose and validate the model that matches the deployment.

The H100 host was removed by the owner. This update adds the reusable
`tools/latency_sweep.py` concurrency benchmark and profile argument tests;
it does not add H100 hardware measurements or claim H100 1q latency or
improvements from max-running values 64/128. The existing hardware results
above remain the evidence for the H100 optimization.
