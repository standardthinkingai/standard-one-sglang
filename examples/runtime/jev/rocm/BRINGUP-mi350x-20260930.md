# eng-decision: decision-mode SGLang fork on MI350X (StandardOne-8B)

Brought up 2026-09-30. Container `eng-decision`, `http://127.0.0.1:30010`
(host network, bound to 127.0.0.1). `POST /v1/systemone` is served by the
engine itself (in-process jev-adapter service + GPU label readout); there
is no separate adapter process and port 30011 is unused.

## Start / stop

```bash
# start (about 30 s to healthy); prints the container id
/opt/engine/launch-eng-decision.sh
until curl -sf http://127.0.0.1:30010/health >/dev/null; do sleep 2; done
# REQUIRED after every start: bit-identical replay of 100 text questions
/opt/di/venv/bin/python /opt/engine/tools/canary.py      # exit 0 = healthy
# stop
docker rm -f eng-decision
```

The script's flags (env overrides: `IMAGE`, `NAME`, `PORT`, `MEM_FRACTION`,
`ATTENTION_BACKEND`; extra args are appended):

```
python3 -m sglang.launch_server --model-path /models/StandardOne-8B \
  --revision 36d7999c63403acc1fd5861d5b139eee275e26d8 --served-model-name standard-one-8b \
  --decision-readout-path /opt/engine/readout/standardone-8b-36d7999c-gpu-readout.npz \
  --host 127.0.0.1 --port 30010 --tp-size 1 --model-impl sglang --dtype bfloat16 \
  --attention-backend triton --context-length 32768 --max-running-requests 32 \
  --mem-fraction-static 0.15 --chunked-prefill-size -1 --mm-preprocess-cache-size-mb 0 \
  --model-config-parser hf --load-format safetensors --disable-radix-cache \
  --disable-decode-cuda-graph --disable-prefill-cuda-graph --decision-deadline-seconds 110
env: JEV_DEFAULT_TEMPERATURE=1.65 JEV_PROMPT_WORDING=served JEV_MODEL_ALIAS=jev-latest HF_HUB_OFFLINE=1
```

About 34 GB of VRAM (16.9 GB weights, 12.3 GB KV for 95,103 tokens).
Served config = current release: served wording, default temperature 1.65
(only when a request omits `options.temperature`), context 32768, model
`standard-one-8b` or alias `jev-latest`.

**Do not switch to `--attention-backend aiter`** (SGLang's ROCm default).
About half of aiter starts come up corrupt (wrong, run-to-run varying
probabilities) and later abort with `Memory access fault by GPU`. The stock
base image shows the same fault; production `sglang` (:30000) died with it at
12:20:13 UTC. `triton` was bit-stable on every start. If `canary.py` ever
fails, `docker rm -f eng-decision` and start again.

## Text request

```bash
curl -s http://127.0.0.1:30010/v1/systemone -H 'Content-Type: application/json' -d '{

    "refund": {"type": "noul", "instructions": "환불을 요청하고 있나요?"},
    "severity": {"type": "score", "instructions": "결제 피해를 분류하세요.",

```

Saved as `/opt/engine/data/smoke-text.json` (`curl ... -d @/opt/engine/data/smoke-text.json`).

## Image request (data URL)

Only base64 `data:image/(png|jpeg|webp);base64,...` URLs are accepted (no
http(s) URLs, no paths). Images are inserted at the start of the user turn,
before the text (positions in the original request are not preserved).

```bash
python3 - <<'EOF' > /tmp/req.json
import base64, json
url = "data:image/png;base64," + base64.b64encode(open("/path/to/screen.png", "rb").read()).decode()
print(json.dumps({"model": "jev-latest", "state": "Look at the screenshot.", "images": [url],
  "questions": {"color": {"type": "choice", "instructions": "What color is the square?",
                          "criteria": {"red": "red", "blue": "blue", "green": "green"}}}}))
EOF
curl -s http://127.0.0.1:30010/v1/systemone -H 'Content-Type: application/json' -d @/tmp/req.json
```

`/opt/engine/data/smoke-image.json` is a ready example (448x448 red square;
657 input tokens, 544 of them image tokens). The first image request after a
start takes about 8 s (vision warm-up); later ones about 80-180 ms.

## Not supported in this mode

`options.return_logprobs: true` and a non-empty `options.assistant_prefix`
(422); more than 255 options per question; `/generate` accepts only the
decision contract (`max_new_tokens: 0`, no logprobs). `options.permutations` and
`options.temperature` work (verified; permutations cost questions x permutations prefills).
